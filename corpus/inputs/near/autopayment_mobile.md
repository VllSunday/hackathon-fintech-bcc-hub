## Часть A. Новый функционал

### Цели

1. Сделать пополнение мобильной связи быстрым и удобным: клиент один раз настраивает автоплатёж и больше не следит за балансом номера.
2. Перевести на автоплатёж не менее 15 % клиентов, которые пополняют мобильную связь вручную каждый месяц, в течение 6 месяцев после запуска.
3. Снизить число обращений в контакт-центр с темой «деньги списались, а связь не пополнилась» за счёт понятных статусов исполнения и уведомлений.

### Термины и сокращения

| Термин | Определение |
| :--- | :--- |
| Автоплатёж | Поручение клиента банку регулярно пополнять баланс указанного номера мобильной связи без подтверждения каждой операции. |
| Автоплатёж по расписанию | Автоплатёж, который исполняется один раз в месяц в выбранный клиентом день на фиксированную сумму. |
| Автоплатёж по балансу | Автоплатёж, который исполняется, когда оператор сообщает, что баланс номера опустился ниже порога, заданного клиентом. |
| Сумма автоплатежа | Сумма, которая зачисляется на баланс номера у оператора связи. |
| Источник списания | Карта KZT или текущий счёт KZT клиента, с которого банк списывает деньги для исполнения автоплатежа. |
| День списания | Число месяца от 1 до 31, выбранное клиентом для автоплатежа по расписанию. |
| Попытка исполнения | Одна попытка списать деньги с источника списания и передать платёж оператору. Первая попытка выполняется планировщиком или по событию о балансе, следующие называются повторными. |
| Период | Для автоплатежа по расписанию — календарный месяц по времени Алматы. |
| Обязательное сервисное уведомление | Уведомление об успешном или неуспешном исполнении и об отключении автоплатежа. Клиент не может отключить такие уведомления в настройках. |
| Статусы автоплатежа | «Активен», «Приостановлен», «Отключён». |
| Статусы исполнения | «В обработке», «Исполнен», «Не исполнен». |

### Архитектура решения

Мобильное приложение → API автоплатежей (часть B) → сервис автоплатежей. Сервис автоплатежей → карточный процессинг или АБС (списание с источника) → платёжный шлюз операторов → оператор связи. Сервис автоплатежей → сервис уведомлений (push и SMS). Оператор связи → платёжный шлюз операторов → сервис автоплатежей: события о снижении баланса номера для автоплатежей по балансу.

### Дизайн процесса UI

Платежи → Мобильная связь → Автоплатёж.

Экран подключения: номер телефона (по умолчанию подставляется номер клиента, его можно изменить), оператор определяется автоматически, переключатель типа «По расписанию / По балансу», поле «Сумма, ₸», поле «День списания» или «Порог баланса, ₸», выбор источника списания, поле «Название» (необязательное) и кнопка «Подключить».

Список автоплатежей: название, номер телефона, статус и дата следующего списания. Карточка автоплатежа: кнопки «Изменить», «Приостановить», «Отключить» и история исполнений. Ошибки ввода показываются под соответствующим полем, ошибки исполнения — в истории и уведомлением.

### Требования к изменениям

#### BPMN схема процесса

Наступление дня списания или событие о балансе → проверка статуса автоплатежа и лимитов → списание с источника → передача платежа оператору → фиксация результата → уведомление клиента. При недостатке средств: ожидание интервала → повторная попытка → после исчерпания попыток статус исполнения «Не исполнен» → уведомление клиента.

#### Функциональные требования

**Подключение автоплатежа**

* **Ф-1.** Подключить автоплатёж может клиент — физическое лицо, у которого в банке есть хотя бы одна активная карта KZT или открытый текущий счёт KZT.
* **Ф-2.** Клиент указывает номер мобильного телефона Казахстана в формате +7 7XX XXX XX XX. Оператор определяется по справочнику номерных ёмкостей; если номер не относится к поддерживаемому оператору, подключение отклоняется с сообщением «Оператор этого номера пока не поддерживается».
* **Ф-3.** Клиент может задать название автоплатежа длиной до 40 символов. Если название не задано, используется название оператора и последние четыре цифры номера, например «Kcell •4521».
* **Ф-4.** Клиент выбирает тип автоплатежа: по расписанию или по балансу. Тип после подключения не меняется.
* **Ф-5.** Сумма автоплатежа — целое число тенге в пределах минимальной и максимальной суммы из таблицы «Общие параметры».
* **Ф-6.** Для автоплатежа по расписанию клиент выбирает день списания, для автоплатежа по балансу — порог баланса из диапазона, указанного в таблице «Общие параметры».
* **Ф-7.** Клиент выбирает источник списания из своих активных карт KZT и открытых текущих счетов KZT. Карты в других валютах и кредитные карты в списке не показываются.
* **Ф-8.** На один номер у клиента может быть не более одного автоплатежа каждого типа: одновременно допускаются один автоплатёж по расписанию и один автоплатёж по балансу. Попытка подключить второй автоплатёж того же типа на этот номер отклоняется с сообщением «Для этого номера уже есть такой автоплатёж».
* **Ф-9.** Если число автоплатежей клиента в статусах «Активен» и «Приостановлен» достигло максимума из таблицы «Общие параметры», кнопка «Подключить» недоступна, а под ней показывается подсказка «Можно подключить не больше 10 автоплатежей».
* **Ф-10.** Подключение подтверждается так же, как разовый платёж в мобильном банке: кодом из SMS или биометрией. После подтверждения автоплатёж получает статус «Активен».

**Исполнение автоплатежа по расписанию**

* **Ф-11.** Планировщик ежедневно во время из таблицы «Общие параметры» выбирает автоплатежи в статусе «Активен», у которых день списания совпадает с текущим числом месяца, и запускает по ним первую попытку исполнения.
* **Ф-12.** Если выбранного дня списания нет в текущем месяце (например, 31-го числа в апреле), автоплатёж исполняется в последний день этого месяца.
* **Ф-13.** Автоплатёж по расписанию исполняется успешно не более одного раза за период.
* **Ф-14.** Планировщик реализуется как cron-задача в кластере Kubernetes, которая выбирает записи из таблицы autopayments по индексу next_run_date пакетами по 500 записей.

**Исполнение автоплатежа по балансу**

* **Ф-15.** Автоплатёж по балансу исполняется, когда от платёжного шлюза операторов приходит событие о том, что баланс номера стал ниже порога, заданного клиентом.
* **Ф-16.** Между двумя успешными исполнениями одного автоплатежа по балансу проходит не менее 24 часов; события о балансе, полученные раньше, игнорируются и записываются в журнал.
* **Ф-17.** Если исполнение автоплатежа по балансу превысит месячный лимит пополнений из таблицы «Общие параметры», оно не выполняется, а клиент получает push-уведомление о достижении лимита.

**Списание и передача платежа оператору**

* **Ф-18.** Банк списывает с источника списания сумму автоплатежа. Комиссия банка не взимается; если оператор связи взимает комиссию за пополнение, она включается в сумму автоплатежа.
* **Ф-19.** После успешного списания платёж передаётся оператору через ЕРП. Если оператор подтвердил зачисление, попытка исполнения получает статус «Исполнен».
* **Ф-19.** После статуса «Исполнен» клиент получает обязательное сервисное уведомление с суммой, номером телефона и источником списания.

**Недостаток средств и повторные попытки**

* **Ф-20.** Если на источнике списания недостаточно средств, попытка исполнения завершается без списания, и через интервал из таблицы «Общие параметры» выполняется повторная попытка — до исчерпания числа повторных попыток.
* **Ф-21.** Повторные попытки автоплатежа по расписанию выполняются только в день списания; на следующий день автоплатёж за этот период больше не исполняется.
* **Ф-22.** Частичное списание не выполняется: банк не пополняет номер на сумму меньше суммы автоплатежа, даже если на источнике есть часть этой суммы.
* **Ф-23.** Когда все попытки исчерпаны, исполнение получает статус «Не исполнен», клиент получает обязательное сервисное уведомление, а автоплатёж остаётся в статусе «Активен».
* **Ф-24.** Если число подряд неисполненных периодов достигло значения из таблицы «Общие параметры», автоплатёж переводится в статус «Отключён» с причиной «Недостаточно средств», и клиент получает обязательное сервисное уведомление.

**Уведомления**

* **Ф-25.** За 1 день до дня списания клиент получает push-уведомление о предстоящем списании с суммой и номером телефона. Например, при дне списания 15 уведомление придёт 13-го числа.
* **Ф-26.** Клиент может отключить push о предстоящем списании в карточке автоплатежа. Обязательные сервисные уведомления отключить нельзя.
* **Ф-27.** Текст push-уведомления о неуспешном исполнении — TBD, согласуется с маркетингом.

**Изменение, приостановка и отключение**

* **Ф-28.** Клиент может изменить сумму, день списания или порог баланса и источник списания, а также переименовать автоплатёж и выгрузить историю исполнений в PDF.
* **Ф-29.** Клиент может приостановить автоплатёж на срок из таблицы «Общие параметры». Во время приостановки автоплатёж не исполняется; по окончании срока его статус автоматически меняется на «Активен».
* **Ф-30.** Клиент может отключить автоплатёж в любой момент. Попытки исполнения, которые ещё не начаты, отменяются. Отключённый автоплатёж нельзя включить снова — можно подключить новый.
* **Ф-31.** Автоплатёж отключается автоматически, если он не исполнен три периода подряд.
* **Ф-32.** В карточке автоплатежа клиент видит историю исполнений за срок из таблицы «Общие параметры»: дату, сумму, источник списания, статус исполнения и причину неуспеха.
* **Ф-33.** Клиент видит и изменяет только свои автоплатежи. На запрос к чужому автоплатежу система отвечает так же, как на запрос к несуществующему, чтобы не раскрывать факт его существования.

### Sequence Diagram

Планировщик → сервис автоплатежей: автоплатежи на сегодня. Сервис автоплатежей → карточный процессинг или АБС: списание суммы с источника. Процессинг или АБС → сервис автоплатежей: результат списания. Сервис автоплатежей → платёжный шлюз операторов: платёж (номер телефона, сумма, идентификатор операции). Платёжный шлюз операторов → сервис автоплатежей: подтверждение зачисления. Сервис автоплатежей → сервис уведомлений: результат исполнения.

### Нефункциональные требования

* **НФ-1.** Планировщик завершает первые попытки исполнения всех автоплатежей дня (до 200 000 автоплатежей) не позднее чем через 60 минут после запуска.
* **НФ-2.** Доступность API автоплатежей для мобильного приложения — не ниже 99,5 %.
* **НФ-3.** Время ответа API автоплатежей на создание и изменение автоплатежа — не более 2 секунд для 95 % запросов при нагрузке до 50 запросов в секунду.
* **НФ-4.** Сервис автоплатежей передаёт уведомление о результате исполнения в сервис уведомлений не позднее 5 минут после получения ответа оператора.
* **НФ-5.** Подключение, изменение, приостановка и отключение автоплатежа записываются в журнал аудита с идентификатором клиента, временем и каналом; журнал хранится 5 лет.

### Требования к данным

Для автоплатежа хранятся: идентификатор, идентификатор клиента, номер телефона, код оператора, тип, название, сумма в тиынах, день списания, порог баланса в тиынах, идентификатор источника списания, статус, дата окончания приостановки, признак push о предстоящем списании и счётчик подряд неисполненных периодов.

Для каждой попытки исполнения хранятся: идентификатор операции, время начала, сумма в тиынах, статус исполнения и код причины неуспеха.

### Требования к интеграции

Мобильное приложение работает с автоплатежами через дочерний документ «Автоплатёж за мобильную связь — REST API» (часть B).

Обмен с платёжным шлюзом операторов синхронный, тайм-аут запроса — 30 000 мс. Каждый платёж передаётся оператору с уникальным идентификатором операции; повторная передача с тем же идентификатором не приводит к повторному зачислению.

### Требования к тестированию

#### Тестирование требований

Тест-кейсы готовит команда тестирования по критериям приёмки ниже. Обязателен регресс разовых платежей за мобильную связь.

### Критерии приемки

| Исходные условия | Действие | Ожидаемый результат |
| :--- | :--- | :--- |
| Автоплатёж по расписанию, день списания 31, сумма 2 000 ₸, на карте достаточно средств | Запуск планировщика 28 февраля 2027 г. и 1 марта 2027 г. | 28 февраля списания нет; 1 марта списано 2 000 ₸ |
| Автоплатёж по расписанию на 3 000 ₸, на карте 1 200 ₸ весь день | Первая и повторные попытки исполнения | После второй повторной попытки исполнение получает статус «Не исполнен», клиент получает уведомление |
| Автоплатёж по балансу, порог 300 ₸, сумма 1 000 ₸ | Оператор сообщает баланс 180 ₸ | Списано 1 000 ₸, баланс номера 1 180 ₸, клиент получает уведомление об исполнении |
| Тот же автоплатёж успешно исполнен 10 часов назад | Приходит событие о балансе 150 ₸ | Исполнения нет, событие записано в журнал |
| Клиент вводит сумму 35 000 ₸ при подключении | Нажать «Подключить» | Под полем «Сумма, ₸» показана ошибка, автоплатёж не создан |

## Часть B. REST API

Дочерний документ части A: «Автоплатёж за мобильную связь — REST API».

Для всех методов: авторизация Bearer, сессия клиента мобильного банка; формат обмена — `application/json`; суммы передаются в тиынах, если в описании поля не указано иное. Если результат 200 или 201 — успешный. Если результат 400, 401 и далее — неуспешный.

### Метод 1. Подключение автоплатежа

#### Общие параметры

| Поле | Значение |
| :--- | :--- |
| **Description** | Подключение автоплатежа. Функциональные требования: Ф-1 – Ф-10 |
| **REST type** | POST |
| **Authorization** | Bearer, сессия клиента |
| **Controller** | AutopaymentController |
| **URL type** | Dev / Prod |
| **Request URL** | Dev: `/api/v1/autopayments` . Prod: `/api/v1/autopayments` |
| **CURL** | `curl -X POST "$BASE/api/v1/autopayments" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"phone":"+77015554521","type":"SCHEDULE","name":"Kcell •4521","amount":200000,"debitDay":5,"sourceId":"card-7781"}'` |
| **Swagger** | `/swagger/autopayments` |
| **Gitlab project** | retail/autopayments-api |
| **Framework** | Spring Boot 3 |
| **Author** | Команда «Регулярные платежи» |
| **Developer** | Команда «Регулярные платежи» |

#### Логика работы метода

1. Проверить пользовательскую сессию.
2. Проверить, что источник списания принадлежит клиенту и активен.
3. Определить оператора по номеру телефона.
4. Проверить сумму, день списания или порог баланса, ограничения на число автоплатежей.
5. Создать автоплатёж в статусе `ACTIVE` и вернуть его идентификатор и дату следующего списания.

#### Request body

| Parameter | Format | Size | Mandatory | Logic | Description | DB field |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `phone` | string | 12 | Да | +77XXXXXXXXX | Номер телефона | `phone` |
| `type` | string | — | Да | SCHEDULE / BALANCE | Тип автоплатежа | `type` |
| `name` | string | 1–40 | Да | Произвольный текст | Название автоплатежа | `name` |
| `amount` | integer | 32 bit | Да | 10 000 – 5 000 000 | Сумма автоплатежа в тиынах | `amount_tiyn` |
| `debitDay` | integer | 2 знака | Для SCHEDULE | 1–31 | День списания | `debit_day` |
| `threshold` | integer | 32 bit | Для BALANCE | 200–5 000 | Порог баланса в тенге | `threshold_tiyn` |
| `sourceId` | string | 1–64 | Да | Карта или текущий счёт клиента | Источник списания | `source_id` |
| `notifyBefore` | boolean | — | Нет | По умолчанию true | Push о предстоящем списании | `notify_before` |

#### Ответ

| Parameter | Format | Logic | Description | DB field |
| :--- | :--- | :--- | :--- | :--- |
| `id` | string | UUID | Идентификатор автоплатежа | `id` |
| `status` | string | ACTIVE | Статус автоплатежа | `status` |
| `nextDebitDate` | string | YYYY-MM-DD, только для SCHEDULE | Дата следующего списания | `next_run_date` |

#### Статусы

**201.** Автоплатёж создан.
```json
{"id":"5b1c0e9a-2f4d-4c43-9a51-0d6c1e7b2a10","status":"ACTIVE","nextDebitDate":"2026-12-05"}
```

**400.** Параметры запроса заполнены неверно.
```json
{"code":"VALIDATION_ERROR","message":"Проверьте сумму"}
```

**401.** Запрос выполнен без необходимой авторизации.
```json
{"code":"UNAUTHORIZED","message":"Требуется вход"}
```

**404.** Источник списания не найден у клиента.
```json
{"code":"SOURCE_NOT_FOUND","message":"Источник списания не найден"}
```

**409.** На номер уже есть автоплатёж этого типа или достигнут максимум автоплатежей клиента.
```json
{"code":"LIMIT_REACHED","message":"Для этого номера уже есть такой автоплатёж"}
```

**422.** Оператор номера не поддерживается.
```json
{"code":"OPERATOR_NOT_SUPPORTED","message":"Оператор этого номера пока не поддерживается"}
```

**500.** Внутренняя ошибка сервера.
```json
{"code":"INTERNAL_ERROR","message":"Ошибка сервиса"}
```

### Метод 2. Изменение автоплатежа

#### Общие параметры

| Поле | Значение |
| :--- | :--- |
| **Description** | Изменение параметров автоплатежа. Функциональные требования: Ф-28 |
| **REST type** | PATCH |
| **Authorization** | Bearer, сессия клиента |
| **Controller** | AutopaymentController |
| **Request URL** | Dev / Prod: `/api/v1/autopayments/{id}` |

#### Логика работы метода

1. Проверить пользовательскую сессию и принадлежность автоплатежа клиенту.
2. Проверить переданные поля по тем же правилам, что и при подключении.
3. Сохранить изменения; поля, которые не переданы, не меняются.
4. Статус автоплатежа этим методом не меняется.

#### Path-параметры

| Parameter | Format | Mandatory | Description |
| :--- | :--- | :--- | :--- |
| `id` | string (UUID) | Да | Идентификатор автоплатежа |

#### Request body

| Parameter | Format | Mandatory | Logic | Description |
| :--- | :--- | :--- | :--- | :--- |
| `name` | string | Нет | 1–40 символов | Новое название |
| `amount` | integer | Нет | Как в методе 1 | Новая сумма в тиынах |
| `debitDay` | integer | Нет | 1–31, только для SCHEDULE | Новый день списания |
| `threshold` | integer | Нет | Как в методе 1, только для BALANCE | Новый порог баланса |
| `sourceId` | string | Нет | Карта или текущий счёт клиента | Новый источник списания |
| `notifyBefore` | boolean | Нет | true / false | Push о предстоящем списании |

#### Статусы

**200.** Изменения сохранены; в ответе — автоплатёж в формате метода 4.
**400.** Параметры запроса заполнены неверно.
**401.** Запрос выполнен без необходимой авторизации.
**404.** Автоплатёж не найден. Для чужого автоплатежа также возвращается 404.
**409.** Автоплатёж в статусе `DISABLED`, изменение невозможно.
**500.** Внутренняя ошибка сервера.

### Метод 3. Отключение автоплатежа

#### Общие параметры

| Поле | Значение |
| :--- | :--- |
| **Description** | Отключение автоплатежа клиентом. Функциональные требования: Ф-30 |
| **REST type** | GET |
| **Authorization** | Bearer, сессия клиента |
| **Controller** | AutopaymentController |
| **Request URL** | Dev / Prod: `/api/v1/autopayments/{id}/disable` |

#### Логика работы метода

1. Проверить пользовательскую сессию и принадлежность автоплатежа клиенту.
2. Перевести автоплатёж в статус `DISABLED` и отменить не начатые попытки исполнения.
3. Повторный вызов для уже отключённого автоплатежа возвращает 200 без изменений.

#### Статусы

**200.** Автоплатёж отключён.
```json
{"id":"5b1c0e9a-2f4d-4c43-9a51-0d6c1e7b2a10","status":"DISABLED"}
```
**401.** Запрос выполнен без необходимой авторизации.
**404.** Автоплатёж не найден, в том числе если он принадлежит другому клиенту.
**500.** Внутренняя ошибка сервера.
