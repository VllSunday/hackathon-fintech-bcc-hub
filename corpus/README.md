# Корпус для оценки агента

Набор документов требований, на которых мы измеряем агента. Без него баланс между кодом и моделью остаётся предположением.

## Структура

| Папка | Что лежит | Назначение |
|---|---|---|
| `inputs/organizers/` | Документ, выданный организаторами | Основной ориентир |
| `inputs/containers/` | Тот же документ в других форматах: PDF с текстовым слоем, PDF-скан, DOCX и HTML, созданные `scripts/make_fixtures.py` | Проверка чтения форматов |
| `inputs/near/` | ТЗ по шаблону организаторов, но про другие фичи: N1 `transfers_by_phone`, N2 `autopayment_mobile` | Незнакомое содержание в знакомой форме |
| `inputs/far/` | Другая форма: user stories (F1 `sme_onboarding_stories`), ТЗ по ГОСТ 34 (F2 `fraud_alerts_gost34`), большой документ (F3 `sme_credit_pipeline_large`) | Незнакомая форма |
| `inputs/degenerate/` | Документ без требований (D1 `marketing_no_requirements`), документ со встроенной инструкцией для ИИ (D2 `injection_note`) | Поведение на краях |
| `gold/` | Эталонная разметка, файл на документ | Ответы для скорера |

## Источник выданного документа

`inputs/organizers/requirements.md` — копия `docs/requirements.md` из репозитория организаторов [BCC-HUB/ai-requirements-validator-task](https://github.com/BCC-HUB/ai-requirements-validator-task), коммит `928c1aa`. Лежит здесь как входной файл для прогонов и тестов, не как результат работы.

## Формат эталонной разметки

Файл `gold/<имя документа>.yaml`. Пример одной записи:

```yaml
document: near/transfers_by_phone.md
defects:
  - id: G-14
    scope: pair             # requirement | pair | set | document
    criterion: set_consistent
    severity: critical      # critical | major | minor
    kind: cross_section
    quotes:                 # дословные цитаты, по которым скорер сопоставит находку агента
      - "Отправитель может выполнить не более 20 переводов по номеру телефона в сутки."
      - "Количество переводов в сутки, не более | 30"
    note: Лимит количества переводов в Ф-8 — 20, в таблице «Лимиты и тарифы» — 30.
  - id: A-05
    adjudicated: true       # добавлен после независимой проверки находки агента
```

Эталоны сгенерированы отдельной моделью вместе с документами. Находки агента вне эталона и уровни серьёзности проверяют независимые оценщики, которые видят только документ; подтверждённые записи помечены `adjudicated: true`. Документ организаторов эталона не имеет: под него мы не подстраивались.

## Оценка

Скорер сравнивает сохранённые прогоны с эталоном и модель не вызывает, поэтому ничего не стоит:

```bash
uv run reqaudit-eval corpus/gold/<документ>.yaml runs/<прогон> [runs/<прогон> ...]
```

Находка агента совпадает с дефектом эталона по месту, а не по словам: её цитаты должны покрывать цитаты эталона, у противоречия — обе стороны. Отчёт показывает полноту (всего и по критичным), точность, совпадение критерия и серьёзности, а для нескольких прогонов — какие дефекты находятся всегда, а какие через раз, и у каких прыгает серьёзность. Находки вне эталона выводятся списком: это ложные срабатывания или дефекты, которые стоит добавить в эталон.

Готовый пример — `gold/tricky.yaml` для `tests/fixtures/tricky.pdf`: документ синтетический, его дефекты заложены при создании.

## Правила

- Чужие документы с неясной лицензией в репозиторий не кладём: храним ссылку и скрипт загрузки.
- Одна правка за цикл оценки; правки общие, под текст конкретного документа ничего не подгоняется.
