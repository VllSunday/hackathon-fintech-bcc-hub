### Цели
Клиент должен быстро и без ошибок переводить деньги знакомым, зная только их номер телефона. Перевести часть переводов по номеру карты в переводы по номеру телефона и тем самым сократить число обращений в поддержку из-за ошибочно введённых реквизитов.

### Термины

| Термин | Определение |
| :--- | :--- |
| АБС | Автоматизированная банковская система, в которой ведутся счета клиентов и проводятся списания и зачисления |
| CIF | Сервис клиентских данных: профиль клиента, подтверждённые номера телефонов, счета |
| Отправитель | Клиент банка, который инициирует перевод в мобильном приложении |
| Получатель | Клиент банка, которому зачисляется перевод |
| Сутки | Период 24 часа, предшествующий моменту проверки лимита |
| Разовый лимит | Минимальная и максимальная сумма одного перевода |
| Дневной лимит | Максимальная сумма переводов по номеру телефона одного отправителя за сутки |
| Пакет «Премиум» | Пакет обслуживания с расширенными лимитами, подключается в отделении |

### Архитектура решения
Мобильное приложение → сервис переводов. Сервис переводов → CIF (поиск получателя по номеру). Сервис переводов → АБС (списание и зачисление). Сервис переводов → сервис уведомлений (push отправителю и получателю).

### Дизайн процесса UI
Платежи → Переводы → По номеру телефона. На первом экране поле номера с выбором из контактов, поле суммы, поле комментария и кнопка «Продолжить». На экране подтверждения показаны получатель, сумма, комиссия и кнопка «Перевести». При ошибке ввода сообщение появляется под соответствующим полем.

### Требования к изменениям

#### BPMN схема процесса
Ввод номера → поиск получателя → ввод суммы → проверка лимитов и расчёт комиссии → подтверждение → списание и зачисление → уведомления → завершение.

#### Функциональные требования
* **Ф-1.** Перевод по номеру телефона доступен клиенту — физическому лицу с активным текущим счётом в тенге, вошедшему в мобильное приложение.
* **Ф-2.** Получатель определяется по номеру мобильного телефона в формате +7XXXXXXXXXX. Получателем может быть только клиент банка с активным текущим счётом в тенге, у которого этот номер подтверждён в профиле.
* **Ф-3.** После ввода номера система показывает имя получателя и первую букву фамилии, например «Айгерим С.». Полная фамилия, ИИН и номер счёта получателя отправителю не показываются.
* **Ф-4.** Отправитель может добавить к переводу комментарий длиной до 140 символов. Комментарий необязателен.
* **Ф-5.** Сумма одного перевода должна находиться в пределах разового лимита из таблицы «Лимиты и тарифы», обе границы включены.
* **Ф-6.** Сумма переводов по номеру телефона одного отправителя за сутки не превышает дневного лимита его пакета обслуживания из таблицы «Лимиты и тарифы».
* **Ф-7.** Счётчики дневного лимита и количества переводов обнуляются в 00:00 по времени Алматы.
* **Ф-8.** Отправитель может выполнить не более 20 переводов по номеру телефона в сутки.
* **Ф-9.** Переводы бесплатны, пока сумма переводов отправителя по номеру телефона с начала календарного месяца, включая текущий перевод, не превышает бесплатного объёма. С части суммы сверх бесплатного объёма взимается комиссия по ставке из таблицы «Лимиты и тарифы», но не более максимальной комиссии за одну операцию.
* **Ф-10.** Комиссия списывается со счёта отправителя сверх суммы перевода, получатель получает сумму полностью. Комиссия не учитывается ни в разовом, ни в дневном лимите.
* **Ф-11.** До подтверждения перевода экран показывает сумму комиссии и остаток дневного лимита.
* **Ф-12.** Если на счёте отправителя недостаточно средств для суммы перевода вместе с комиссией, перевод отклоняется с сообщением «Недостаточно средств», списание не выполняется.
* **Ф-13.** Если перевод превышает разовый или дневной лимит либо допустимое количество переводов, он отклоняется с сообщением «Превышен лимит» и указанием остатка дневного лимита в тенге.
* **Ф-14.** Перевод на номер, подтверждённый в профиле самого отправителя, недоступен: вместо кнопки «Продолжить» приложение предлагает перевод между своими счетами.
* **Ф-15.** Каждый запрос на перевод содержит ключ идемпотентности. Повторный запрос с тем же ключом в течение 24 часов возвращает результат исходного перевода и не создаёт новый.
* **Ф-16.** После выполнения перевода система отправляет push отправителю и получателю, добавляет получателя в список «Недавние» на главном экране переводов и формирует квитанцию в PDF, доступную для скачивания.
* **Ф-17.** Остаток дневного лимита хранится в Redis с ключом по идентификатору клиента и временем жизни до 00:00 по Алматы.
* **Ф-18.** Выполненный перевод отображается в истории операций отправителя и получателя со статусом «Выполнен», суммой и комментарием.
* **Ф-19.** Если номер не принадлежит клиенту банка или у клиента нет активного текущего счёта в тенге, приложение показывает сообщение «Получатель не найден», кнопка «Продолжить» недоступна.

#### Лимиты и тарифы

| Параметр | Значение |
| :--- | :--- |
| Разовый лимит: минимальная сумма | 100 ₸ |
| Разовый лимит: максимальная сумма | 300 000 ₸ |

| Ставка комиссии сверх бесплатного объёма | 1 % |

### Sequence Diagram
Приложение → сервис переводов: найти получателя по номеру. Сервис переводов → CIF: клиент и счёт по номеру телефона. Сервис переводов → приложение: имя получателя. Приложение → сервис переводов: создать перевод. Сервис переводов → АБС: списать сумму и комиссию, зачислить сумму. Сервис переводов → сервис уведомлений: push отправителю и получателю.

### Нефункциональные требования
* **НФТ-1.** Ответ на поиск получателя по номеру возвращается не более чем за 2 секунды для 95 % запросов при нагрузке до 50 запросов в секунду.
* **НФТ-2.** Доступность сервиса переводов по номеру телефона — 99,9 %.
* **НФТ-3.** Сведения о каждом переводе (отправитель, получатель, сумма, комиссия, время, статус) хранятся в журнале операций не менее 5 лет.

### Требования к данным
* **ДН-1.** Все суммы в сервисе переводов хранятся и передаются в тиынах целым числом; в интерфейсе они отображаются в тенге.

### Требования к интеграции
* **ИН-1.** Сервис переводов выполняет списание у отправителя и зачисление получателю синхронным вызовом АБС в рамках одного запроса на перевод.
* **ИН-2.** Поиск получателя выполняется через CIF по подтверждённому номеру телефона. Приложение вызывает методы, описанные в части B.

## Часть B. REST API

Дочерний документ части A: «Переводы по номеру телефона — REST API».

### B.1. Поиск получателя

#### Общие параметры

| Поле | Значение |
| :--- | :--- |
| **Description** | Поиск получателя по номеру телефона. Функциональные требования: Ф-2, Ф-3, Ф-19 |
| **REST type** | POST |
| **Authorization** | Bearer, сессия отправителя |
| **Controller** | P2PPhoneController |
| **Request URL** | `/p2p/phone/lookup` |

#### Request body
* **Content-Type:** `application/json`.

| Parameter | Format | Size | Mandatory | Logic | Description |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `phone` | string | 12 | Да | +7XXXXXXXXXX | Номер получателя |

#### Ответ

| Parameter | Format | Logic | Description |
| :--- | :--- | :--- | :--- |
| `found` | boolean | true / false | Найден ли получатель |
| `recipientName` | string | При found = true | Имя получателя для показа |

**200.** Запрос обработан; если получатель не найден, `found` = false.
```json
{"found":true,"recipientName":"Айгерим Сапарова"}
```
**400.** Номер не соответствует формату.  
**401.** Нет действующей сессии.  
**500.** Внутренняя ошибка сервиса.

### B.2. Создание перевода

#### Общие параметры

| Поле | Значение |
| :--- | :--- |
| **Description** | Создание перевода по номеру телефона. Функциональные требования: Ф-4 – Ф-15 |
| **REST type** | POST |
| **Authorization** | Bearer, сессия отправителя |
| **Controller** | P2PPhoneController |
| **Request URL** | `/p2p/phone/transfers` |

#### Логика работы метода
1. Проверить сессию отправителя и ключ идемпотентности.
2. Найти получателя в CIF по номеру; если не найден — вернуть 404 с кодом RECIPIENT_NOT_FOUND.
3. Проверить разовый лимит, дневной лимит и количество переводов за сутки.
4. Рассчитать комиссию по правилу Ф-9.
5. Проверить достаточность средств на сумму перевода и комиссию.
6. При превышении лимита или недостатке средств вернуть 422 с кодом LIMIT_EXCEEDED или INSUFFICIENT_FUNDS.
7. Списать сумму и комиссию в АБС, зачислить сумму получателю, вернуть 201 со статусом COMPLETED.

#### Параметры запроса

##### Headers

| Parameter | Format | Size | Mandatory | Description |
| :--- | :--- | :--- | :--- | :--- |
| `Idempotency-Key` | string | UUID | Да | Ключ идемпотентности, генерируется приложением на каждый перевод |

##### Request body
* **Content-Type:** `application/json`.

| Parameter | Format | Size | Mandatory | Logic | Description |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `phone` | string | 12 | Да | +7XXXXXXXXXX | Номер получателя |
| `amount` | integer | 64 bit | Да | 10 000–30 000 000 | Сумма перевода в тиынах |
| `comment` | string | 1–255 | Да | Произвольный текст | Комментарий к переводу |

#### Ответ
Если результат 201 — успешный. Если результат 400, 401 и далее — неуспешный.

| Parameter | Format | Logic | Description |
| :--- | :--- | :--- | :--- |
| `transferId` | string | При успехе | Идентификатор перевода |
| `status` | string | COMPLETED | Статус перевода |
| `amount` | integer | При успехе | Сумма перевода в тиынах |
| `fee` | integer | При успехе | Комиссия в тиынах |
| `dailyRemaining` | integer | При успехе | Остаток дневного лимита, ₸ |
| `code` | string | При ошибке | Код ошибки |
| `message` | string | При ошибке | Текст ошибки для показа клиенту |

#### Статусы

**201.** Перевод выполнен.
```json
{"transferId":"tr-58f1","status":"COMPLETED","amount":15000000,"fee":0,"dailyRemaining":85000000}
```
**400.** Параметры запроса заполнены неверно.
```json
{"code":"BAD_REQUEST","message":"Проверьте сумму и номер"}
```
**401.** Нет действующей сессии.
```json
{"code":"UNAUTHORIZED","message":"Требуется вход"}
```
**404.** Получатель не найден.
```json
{"code":"RECIPIENT_NOT_FOUND","message":"Получатель не найден"}
```
**500.** Внутренняя ошибка сервиса.
```json
{"code":"INTERNAL_ERROR","message":"Сервис временно недоступен"}
```
